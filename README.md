# Просмотрщик 3D-модели

Просмотрщик на Three.js: показывает 3D-модель в браузере и позволяет примерять
на неё разные дизайны (текстуры). Освещение — HDRI (IBL), под моделью мягкая
тень без видимой плоскости.

## Запуск

Страница грузит модули и ассеты по HTTP, поэтому открывайте её через локальный
сервер, а не двойным кликом по `index.html`:

```bash
python -m http.server 8000
# затем откройте http://localhost:8000
```

Three.js подключается с CDN через import map в `index.html`.

## Управление

Мышь: зажатая левая кнопка — вращение, колесо — зум, правая кнопка —
панорамирование. Остальное — на нижней панели и на клавишах:

| Действие                    |    Кнопка    | Клавиша |
| --------------------------- | :----------: | :-----: |
| Сменить фон                 | `background` |   `B`   |
| Автоповорот вкл/выкл        | `autorotate` |   `A`   |
| Сохранить скриншот          | `screenshot` |   `S`   |
| Полноэкранный режим         | `fullscreen` |   `F`   |
| Заменить дизайн             |  `texture`   |    —    |

## Данные заказа (Битрикс)

Страница собирается под конкретный заказ: модель, дизайн, тип картона и все
тексты правой панели приходят снаружи, в коде лежат только значения по
умолчанию. Модель подбирается по номенклатуре (`DW80-280` → нужный `.glb`), тип
картона задаёт шероховатость (мелованный `0.2`, немелованный `0.8`).

- **Как передать данные, что можно передать, номенклатура и картон** —
  [`docs/integration.md`](docs/integration.md)
- Справочники правятся в [`js/data/catalog.js`](js/data/catalog.js), значения по
  умолчанию — в [`js/data/order.js`](js/data/order.js)

Быстрая проверка без бэкенда — параметрами адреса:

```
?sku=DW80-280&paper=uncoated&texture=/upload/design.png
```

## Настройка

Почти всё, что обычно нужно менять, лежит в `js/config.js` — логику трогать не
требуется.

### Своя модель

Перетащите `.glb`/`.gltf` на страницу или пропишите путь в конфиге (обычно
модель приходит из данных заказа, см. выше):

```js
assets: {
  model: 'assets/models/8cups.glb',
  texture: 'assets/textures/design.png',
}
```

Модель сама центрируется, масштабируется и попадает в кадр.

### Свой дизайн (текстура)

Нажмите **Заменить дизайн**, перетащите картинку на страницу или вызовите из
консоли:

```js
replaceTexture('assets/textures/mockup.jpg');
```

Дизайн меняется на месте — модель не перезагружается.

### Шероховатость поверхности под дизайном

`8cups.glb` приходит с `roughness: 0` на меше, куда ложится текстура (зеркало),
`roughnessMap` на материале нет — всё решает один скаляр:

```js
texturedSurface: {
  roughness: 0.8,   // 0 — зеркало, 1 — полностью матовая
  metalness: 0.0,
}
```

| Значение | Как выглядит                  |
| -------: | ----------------------------- |
|      0.0 | зеркало / глянцевый пластик   |
|      0.2 | лакированная поверхность      |
|      0.8 | матовая печать на бумаге      |
|      1.0 | полностью матовая, без бликов |

Настройка применяется только к мешам под дизайн (`texturableMeshes`); остальная
геометрия (ободок, дно) сохраняет исходные материалы. `null` вместо числа —
«не трогать это свойство». Подобрать значение вживую можно из консоли:

```js
setRoughness(0.35);
setMetalness(0);
```

### Фон

Четыре варианта, переключаются кнопкой или клавишей `B`:

```js
backgrounds: ['#ffffff', '#e8e8e8', '#9a9a9a', '#1c1c1e'],
```

### Иконки

Иконки панели — обычные `.svg` в `assets/icons/`, подключённые тегами `<img>`.
Чтобы поставить свои, замените файл под тем же именем — разметку и CSS трогать не
нужно. Размер задаёт переменная `--icon-size` в `css/style.css`; иконки рисуются
своими цветами (в комплектных залит белый — под тёмную панель).

## Как устроен рендер

### Освещение (IBL)

Свет берётся из equirectangular-HDRI в `assets/hdri/main.hdr`. Карта проходит
через `PMREMGenerator` — предварительную фильтрацию, из-за которой глянцевые и
шероховатые материалы не «искрят»: для каждого уровня шероховатости строится свой
корректно размытый мип.

Карта назначается **только** в `scene.environment`, но не в `scene.background` —
поэтому фон остаётся управляемым плоским цветом, а модель освещена полным
динамическим диапазоном HDRI. Дополнительно: тонмаппинг ACES Filmic, корректный
sRGB-конвейер и анизотропная фильтрация текстур по максимуму видеокарты.

Поддерживаются оба формата — `.hdr` и `.exr`; загрузчик выбирается по расширению.

### Два режима вращения

- **Автоповорот** крутит саму модель (`pivot.rotation.y`), камера неподвижна.
  HDRI живёт в мировых координатах, поэтому блики и отражения остаются на месте.
- **Мышью** вращается камера (`OrbitControls`), модель стоит — взгляд движется
  сквозь окружение, свет и модель поворачиваются вместе.

Собственный `autoRotate` у `OrbitControls` выключен намеренно: он вращал бы
камеру, из-за чего карта света «поехала» бы вместе с ней. Скорость и включённость
автоповорота — в конфиге:

```js
autoRotate: { enabled: true, speed: 0.45 },  // радиан в секунду
```

### Тень, согласованная с HDRI

При загрузке карта сканируется на самое яркое пятно (солнце), и параметры тени
берутся прямо из него — направление, ширина полутени и плотность. Тень падает
туда, куда велит окружение.

```js
sunFromHDRI: {
  enabled: true,        // false — вернуться к ручному position
  distance: 1,
  intensityScale: 0,    // см. ниже
  useColor: true,       // взять оттенок света из самого солнца
}
```

Что нашлось в карте, можно посмотреть из консоли:

```js
describeSun()
// { elevation, azimuth, direction, color, irradiance, angularRadius,
//   contrast, shadow: { blur, opacity } }
```

**Почему `intensityScale: 0`.** Это не «выключено», а осознанный выбор. HDRI уже
освещает модель вместе с солнцем; любая ненулевая интенсивность здесь добавила бы
вторую копию того же солнца. На тень это не влияет — она берёт направление солнца
из карты напрямую. Поднимите до 0.5–1, только если сознательно хотите жёсткий
блик поверх окружения.

### Тень без видимой плоскости

Тень **не** берётся из карты теней. Модель рендерится сверху в offscreen-таргет
depth-материалом, результат размывается двумя проходами гауссианы и кладётся на
плоскость под моделью (она автоматически встаёт на нижнюю точку модели).

Сравнения глубин нет нигде — а значит неоткуда взяться shadow acne, peter-panning
и light bleeding: все они артефакты именно сравнения. Настраивать `bias` не нужно,
потому что смещать нечего.

Форма тени выводится из HDRI:

| измерение в карте  | что задаёт                                    |
| ------------------ | --------------------------------------------- |
| направление солнца | куда отброшена тень (сдвиг матрицы проекции)  |
| `angularRadius`    | ширина полутени (`2·d·tan θ`)                 |
| `peak / mean`      | плотность ядра (солнце против заполняющего)   |

```js
contactShadow: {
  enabled: true,
  size: 2, resolution: 2048, height: 0.9, darkness: 1.3,
  matchHDRI: true,      // false — задать blur и opacity вручную
  minOpacity: 0.1, maxOpacity: 0.6,
}
```

Что из карты получилось — в `describeSun().shadow`.

## Структура

```
index.html                 разметка
css/                       стили
js/config.js               настройки (камера, свет, HDRI, тень, фон и т.д.)
js/main.js                 точка входа
js/Viewer.js               связывает всё вместе, владеет циклом отрисовки
js/core/scene.js           сцена
js/core/camera.js          камера
js/core/renderer.js        рендерер и цветовой конвейер
js/core/lighting.js        источники света (опциональный ключевой свет)
js/core/environment.js     загрузка HDRI, предфильтрация (IBL), поиск солнца
js/core/contactShadow.js   мягкая тень: рендер в текстуру + размытие
js/core/controls.js        OrbitControls
js/core/turntable.js       поворотный круг под моделью (объект сцены)
js/data/catalog.js         номенклатура → модель, картон → шероховатость
js/data/order.js           данные заказа: Битрикс, endpoint, умолчания
js/loaders/                загрузка модели и текстур
js/ui/UIManager.js         кнопки, горячие клавиши, drag & drop
js/ui/approval.js          страница согласования: вкладки, чек-лист, правки
js/ui/orderPanel.js        отрисовка правой панели из данных заказа
js/ui/unwrap.js            вкладка «Развёртка»: просмотр макета с зумом
js/utils/                  общие вспомогательные функции
docs/integration.md        подключение к Битриксу
docs/icons-prompt.md       задание на иконки нижней панели
assets/hdri/               карта освещения (main.hdr)
assets/icons/              svg-иконки панели
assets/models/             модели
assets/textures/           текстуры/дизайны
```
