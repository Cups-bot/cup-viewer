# cup-viewer — страница согласования макета

Клиент типографии открывает персональную ссылку и видит свой будущий стакан в 3D:
может покрутить его, рассмотреть макет плоско на вкладке «Развёртка», согласовать
или запросить правки.

Для IT-отдела — как развернуть и как подключить к Битриксу:
[`docs/integration.md`](docs/integration.md).

> **Чего пока нет.** Кнопка «Согласовать» и форма правок ничего не отправляют на
> сервер: бэкенда для них не существует. Что нужно дописать — в
> [`docs/integration.md`](docs/integration.md), раздел «Что осталось сделать».

---

## 1. Быстрый старт

```bash
npm install
npm start
```

Откроется <http://localhost:8000>.

Двойным кликом по `index.html` страница не заработает: браузер запрещает
JS-модулям и 3D-файлам грузиться с диска, нужен HTTP-сервер.

## 2. Где что править

Главная таблица этого файла. Если непонятно, куда лезть за изменением, — сюда.

| Хочу изменить | Файл |
| --- | --- |
| Текст, зависящий от заказа: статус, заголовок, описание, характеристики, пункты чек-листа | `js/data/order.js` → `DEFAULT_ORDER` |
| Любой другой текст: подписи кнопок, вкладки, подсказки, заголовок вкладки браузера | `index.html` |
| Цвета, отступы, шрифты, поведение на телефоне | `css/approve.css` |
| Свет, камера, фоны, шероховатость бумаги, размер тени | `js/config.js` |
| Какая 3D-модель под какую номенклатуру, шероховатость картона | `js/data/catalog.js` |
| Иконки панели | заменить файл в `assets/icons/` под тем же именем |
| 3D-модель, макет, карта освещения | `assets/models/`, `assets/textures/`, `assets/hdri/` |

**После правки любого файла в `js/` нужно выполнить `npm run build`.** Браузер
читает не исходники, а собранный `dist/cup-viewer.js` — почему так, см. раздел 5.
Чтобы не запускать сборку руками при каждой правке:

```bash
npm run watch
```

### Почему текст разложен на две части

Раньше он был продублирован: одни и те же строки лежали и в `index.html`, и в
JS. Правка в разметке ничего не давала — JS перезаписывал её при загрузке, и в
этот момент успевала мелькнуть старая версия. Теперь правило жёсткое:

- **зависит от заказа** (у каждого клиента своё) → приходит из Битрикса, а
  умолчания лежат в `js/data/order.js`. В `index.html` эти места **пустые**, и
  писать туда текст бесполезно;
- **не зависит от заказа** (одинаково всегда) → прямо в `index.html`.

Подписи кнопки согласования — тоже в разметке, в `data-label-*` на самой кнопке:
JS только переключает состояние, а текст не придумывает.

## 3. Как устроена страница

```
index.html ──> dist/cup-viewer.js (собранный JS)
                  │
                  ├── js/main.js ......... точка входа: поднимает сцену, грузит заказ
                  │     ├── js/data/order.js ..... собирает заказ из всех источников
                  │     ├── js/ui/orderPanel.js .. заполняет правую панель
                  │     └── js/Viewer.js ......... 3D-сцена целиком
                  │
                  └── js/ui/approval.js .. вкладки, чек-лист, форма правок, подсказка
```

### Откуда берутся данные заказа

Приоритет — сверху вниз, что выше, то важнее:

| Источник | Когда используется |
| --- | --- |
| Параметры адреса `?sku=…&texture=…` | только на `localhost`, для проверки руками |
| `window.ORDER_DATA` | шаблон Битрикса печатает объект прямо в страницу — основной способ |
| Запрос на сервер | если задан `config.order.endpoint` и в адресе есть `?order=…` |
| `DEFAULT_ORDER` в `js/data/order.js` | всё остальное, когда данных не пришло |

Всё, что пришло снаружи, проходит проверку в `js/data/sanitize.js`: незнакомые
поля выбрасываются, длинные строки режутся, а путь к файлу принимается только
свой — чужой домен или `javascript:` не пройдут. Страница обязана открыться в
любом случае, поэтому непрошедшее поле молча заменяется значением по умолчанию,
а причина пишется в консоль браузера.

### Что делает `js/Viewer.js`

Это «дирижёр» 3D-сцены. Он собирает вместе части из `js/core/` и владеет циклом
отрисовки:

| Файл | За что отвечает |
| --- | --- |
| `core/scene.js`, `core/camera.js` | сцена и камера — по три строки каждый |
| `core/renderer.js` | вывод картинки и цветовой конвейер |
| `core/studioEnvironment.js` | студия из софтбоксов — источник света и бликов |
| `core/postprocessing.js` | затенение складок, сглаживание, тонмаппинг |
| `core/environment.js` | загрузка панорамы из файла, если она включена |
| `core/lighting.js` | источники света (в текущей настройке почти не используются) |
| `core/contactShadow.js` | мягкая тень под стаканом |
| `core/controls.js` | вращение камеры мышью |
| `core/turntable.js` | поворотный круг под стаканом |
| `loaders/ModelLoader.js` | загрузка `.glb` и подгонка модели под кадр |
| `loaders/TextureManager.js` | загрузка макета и наложение его на модель |
| `ui/UIManager.js` | кнопки панели и горячие клавиши |

## 4. Ключевые решения — почему сделано именно так

Раздел для того, чтобы код не выглядел магией.

### Свет — это отражение софтбоксов, а не лампы

Блик на мелованном картоне — не «свет», а **отражение** окружающих предметов.
Точечная лампа отражается в глянце точкой, и поверхность читается как пластик.
Предметный фотограф ставит софтбоксы — большие светящиеся прямоугольники, — и
глянец отражает их вытянутыми мягкими полосами. Именно эти полосы мозг опознаёт
как «лощёная бумага».

Поэтому окружение убрать нельзя: без него мелованный и немелованный картон
выглядят одинаково. Но и файл-панорама не нужен — студия собирается прямо в коде
из нескольких прямоугольников: [`js/core/studioEnvironment.js`](js/core/studioEnvironment.js).

| | Панорама из файла | Студия в коде |
| --- | --- | --- |
| Вес | мегабайты | 0 байт |
| Цвет | случайные окна и стены пачкают макет | чистый нейтральный |
| Правка | искать другой файл | подвинуть строку в таблице софтбоксов |

Раскладка описана таблицей в начале модуля: ключевой софтбокс, заполняющий,
контровой и две узкие вертикальные полосы. Полосы там ради глянца — на
мелованном картоне они дают чёткие штрихи вдоль стенки, на немелованном
размазываются в еле заметное свечение. Разница между картонами видна на глаз.

Файл-панораму всё ещё можно подключить, если фотограф отдаст свой студийный HDRI:

```js
lighting: { environment: 'hdri' }   // вместо 'studio'
```

### Затенение складок (ambient occlusion)

Без него предмет выглядит наклейкой: свет из окружения приходит со всех сторон
одинаково, и внутренний угол стакана освещён так же ярко, как открытая стенка.

Считает [`js/core/postprocessing.js`](js/core/postprocessing.js) по уже
отрисованному кадру — по глубине и нормалям находит места, куда свет физически
не мог бы достать, и притемняет их.

Тонкость: **наружная стенка стакана выпуклая, затенять на ней нечего.** Реальная
окклюзия возникает только там, где предмет подходит к опоре. Поэтому под стакан
подставляется невидимая плоскость, которую видит только расчёт AO, — из-за неё
у основания появляется плотное затемнение, и стакан перестаёт парить.

Подобрать силу и радиус вживую: `cupViewer.debugAO(true)` покажет только карту
затенения, `cupViewer.debugAO(false)` вернёт картинку.

### Микрорельеф бумаги

Идеально гладкая стенка отражает свет ровно по всей поверхности, и материал
читается как пластик. У настоящей бумаги есть волокно: по отдельности оно
неразличимо, но блик на нём чуть «дрожит» — и это опознаётся как картон.

Рельеф задаётся картой нормалей, а не геометрией: полигонов не прибавляется
вовсе. Карта строится процедурно в
[`js/core/paperSurface.js`](js/core/paperSurface.js) и весит ноль байт.

Все частоты шума там высокие намеренно. Добавьте низкую — и вместо бумаги
получится штукатурка: крупные пятна глаз читает как рельеф предмета, а не как
фактуру материала. Сила настраивается:

```js
texturedSurface: { paperRelief: 0.22 }   // 0 — гладко, 0.5 — крафт
```

### Фон рисует CSS, а не сцена

Холст прозрачный. Причина — тонмаппинг: он применяется последним проходом ко
всему кадру целиком, вместе с заливкой фона, и светло-голубой `#eaf5ff`
превращался в невнятный серый. Подобрать «нужный» цвет заранее нельзя, формула
нелинейная.

Прозрачный холст поверх CSS-фона снимает вопрос: цвет ровно тот, что записан в
`backgrounds` в конфиге, а фон сцены и фон страницы физически не могут разойтись.

Заливка не плоская: за предметом мягкое световое пятно, к краям — притемнение.
Так снимают в студии — предмет отделяется от фона перепадом яркости, а не только
контуром. Геометрия пятна описана один раз в
[`js/core/backdrop.js`](js/core/backdrop.js), потому что нужна дважды: CSS рисует
её на странице, canvas — при сохранении снимка.

Из-за прозрачного холста снимок собирается заново: сначала тот же фон, сверху
сцена. Снимать напрямую с холста нельзя — получится стакан на пустоте, а
прозрачность в PNG большинство просмотрщиков покажет чёрным или клеткой.

### Тень нарисована, а не рассчитана

Обычные 3D-тени часто дают артефакты: полосы, отрыв тени от предмета, засветы.
Здесь тень делается иначе: модель рендерится сверху в отдельную картинку,
картинка размывается и кладётся на пол под стаканом. Никаких артефактов
принципиально быть не может, настраивать нечего.

Направление, мягкость и плотность тени берутся из самой карты освещения: код
находит на панораме самое яркое пятно (солнце или окно) и разворачивает тень
туда же. Поэтому тень выглядит согласованной со светом.

Посмотреть, что нашлось — в консоли браузера: `cupViewer.describeSun()`.

### Вращается модель, а не камера

При автоповороте крутится сам стакан, камера стоит. Если бы вращалась камера,
вместе с ней «поехали» бы блики и отражения — стакан выглядел бы неестественно.
При перетаскивании мышью, наоборот, вращается камера: это привычный облёт.

### Кадр рисуется не всегда

Пока на экране ничего не меняется (клиент читает характеристики, смотрит
развёртку), сцена не перерисовывается. Иначе телефон 60 раз в секунду рисовал бы
одну и ту же картинку и грелся. Свёрнутая вкладка останавливает отрисовку
полностью.

Если добавляете что-то, что меняет сцену, — вызовите `viewer.invalidate()`
(или `viewer.invalidateModel()`, если сдвинулась сама модель: тогда пересчитается
ещё и тень). Без этого изменение может не появиться на экране.

### Макет уменьшается при загрузке

Макеты приходят в печатном разрешении — 7000 пикселей по ширине норма. Видеокарта
телефона такую картинку либо не примет вовсе, либо займёт под неё почти всю
доступную память. Поэтому на модель кладётся уменьшенная копия (потолок —
`config.texture.maxSize`, по умолчанию 2048 px).

Для вкладки «Развёртка», где смотрят мелкий текст, можно передать отдельным полем
`unwrap` крупный исходник — он показывается плоско и на видеокарту не попадает.

### Развёртка рисуется в canvas

Простая картинка при увеличении показывала бы не детали макета, а увеличенные
пиксели экрана. Здесь макет каждый раз перерисовывается из исходного файла в
физических пикселях устройства, поэтому приближение упирается только в
разрешение самого файла.

## 5. Зачем нужна сборка

Браузер загружает один файл `dist/cup-viewer.js`, а не два десятка файлов из
`js/`. Три причины:

1. **Библиотека three.js лежит внутри нашего кода.** Раньше она грузилась со
   стороннего сайта (unpkg.com) — если тот недоступен, страница не открывается
   вовсе, а если его подменят, на странице клиента исполнится чужой код.
2. **Совместимость.** Прежний способ подключения модулей не поддерживает Safari
   старше версии 16.4 — на таких iPhone страница не открывалась и не сообщала об
   этом.
3. **Обновления доезжают до клиента.** Сборка дописывает к адресам файлов метку
   версии (`?v=a1b2c3d4`), и браузер не отдаёт закешированную старую версию.

`dist/` лежит в репозитории, поэтому **на сервере Node не нужен** — достаточно
скопировать файлы. Node нужен только тому, кто правит `js/`.

| Команда | Что делает |
| --- | --- |
| `npm run build` | собрать один раз |
| `npm run watch` | пересобирать при каждой правке |
| `npm run serve` | только локальный сервер |
| `npm start` | собрать и запустить |

## 6. Управление сценой

Мышь: левая кнопка — облёт камерой, колесо — зум, правая — сдвиг, двойной клик —
вернуть исходный вид. Круг под стаканом вращает сам стакан, свет остаётся на
месте.

| Действие | Кнопка | Клавиша |
| --- | :---: | :---: |
| Автоповорот | стрелки по кругу | `A` |
| Снимок сцены | камера | `S` |
| Во весь экран | рамка | `F` |
| Сменить фон | кружочки справа сверху | `B` |
| Поворотный круг | круг | — |
| Как управлять | «i» | — |

Горячие клавиши молчат, пока курсор стоит в поле ввода, — иначе буква, набранная
в форме правок, запускала бы скачивание снимка.

## 7. Настройки в `js/config.js`

Файл прокомментирован построчно; ниже — то, что трогают чаще всего.

### Шероховатость бумаги

Главная настройка внешнего вида. У материала под макетом один параметр:

```js
texturedSurface: {
  roughness: 0.8,   // 0 — зеркало, 1 — полностью матовая
}
```

| Значение | Как выглядит |
| ---: | --- |
| 0.2 | мелованная бумага, лак — собранный блик |
| 0.8 | немелованная, обычная печать — рассеянный свет |

Обычно значение приходит из заказа по типу картона (`js/data/catalog.js`), а не
берётся отсюда.

### Качество картинки

```js
quality: {
  postProcessing: true,      // затенение складок + сглаживание
  msaaSamples: 4,            // сглаживание краёв
  ambientOcclusion: {
    intensity: 1,
    radius: 0.09,            // в мировых единицах, модель ~0.5
    scale: 1.1,
    samples: 16,
  },
}
```

`radius` — самый важный параметр. Больше — затенение расползается широкими
пятнами, меньше — видно только в самых узких щелях. Подбирать с включённым
`cupViewer.debugAO(true)`.

`postProcessing: false` возвращает прямую отрисовку без AO — на случай, если
где-то обнаружится несовместимость.

### Сколько полигонов выдержит модель

Измерено на встроенной видеокарте AMD (Ryzen), то есть на слабом офисном
ноутбуке, с включённой постобработкой:

| Треугольников | Кадр | Частота |
| ---: | ---: | ---: |
| 2 400 (сейчас) | 5,0 мс | 200 к/с |
| 65 000 | 5,0 мс | 200 к/с |
| 250 000 | 5,6 мс | 180 к/с |
| 810 000 | 7,0 мс | 144 к/с |

Бюджет на 60 к/с — 16,6 мс. Запас более чем десятикратный.

**Текущая модель — 2 364 треугольника, из них на печатную стенку приходится 192.**
Окружность разбита примерно на 48–64 сегмента, поэтому силуэт заметно гранёный —
это сейчас главный потолок качества, а вовсе не производительность.

Что просить у 3D-специалиста:

- **150 000–300 000 треугольников** — комфортно даже на телефоне, силуэт
  идеально гладкий. Разумная цель.
- До 800 000 — всё ещё нормально на компьютере, на слабом телефоне возможны
  просадки.
- Окружность: **не меньше 256 сегментов**, лучше 384.
- Обязательно: сглаженные нормали, а на печатной стенке — base-color текстура
  (по её наличию просмотрщик и находит, куда класть макет).
- Модель со сжатием Draco — распаковщик уже лежит в `vendor/draco/`.

Ограничение не в полигонах, а в весе файла: 300 000 треугольников без сжатия —
это несколько мегабайт на загрузку. Draco ужимает такую модель в 5–10 раз.

### Приём перетаскиваемых файлов

```js
ui: { dragAndDrop: false }
```

Выключено намеренно. На клиентской странице брошенный на неё файл подменил бы
согласуемый макет, и кнопка «Согласовать» зафиксировала бы не то, что прислала
типография. Включать только для отладки.

### Снимок сцены

```js
ui: { screenshotShare: 'auto' }
```

`auto` — скачивать файлом. Системное окно «Поделиться» открывается только на
iPhone и iPad, где Safari иначе не даёт сохранить картинку.

### Безопасность

```js
security: {
  urlOverrides: 'localhost',                       // 'never' | 'localhost' | 'always'
  allowedAssetPrefixes: ['assets/', '/upload/'],
  debugApi: 'localhost',
}
```

`urlOverrides` — разрешить ли параметрам адреса подменять данные заказа. На бою
это опасно: по ссылке `?texture=…&title=Заказ+аннулирован` клиенту можно показать
чужой макет и чужой текст на вашем же домене. Поэтому по умолчанию канал открыт
только на локальной машине.

## 8. Проверка из консоли браузера

Работает на `localhost` (управляется `security.debugApi`):

```js
cupViewer.order                            // какие данные применились
cupViewer.applyOrder({ paper: 'coated' })  // подменить тип картона на лету
cupViewer.applyOrder({ sku: 'DW90-430' })  // другая модель
cupViewer.setRoughness(0.35)               // покрутить шероховатость руками
cupViewer.describeSun()                    // что нашлось в карте освещения
```

## 9. Структура файлов

```
index.html                 разметка страницы и весь текст, не зависящий от заказа
dist/cup-viewer.js         собранный код — то, что читает браузер
css/style.css              базовые стили просмотрщика
css/approve.css            оформление страницы и адаптив под телефоны
js/config.js               настройки: камера, свет, тень, фоны, безопасность
js/main.js                 точка входа
js/appState.js             связь между сценой и интерфейсом
js/Viewer.js               3D-сцена, цикл отрисовки
js/core/                   части сцены: рендерер, свет, тень, камера, круг
js/core/studioEnvironment.js  студия из софтбоксов — источник бликов
js/core/postprocessing.js     затенение складок, сглаживание, тонмаппинг
js/core/layers.js             какой объект какая камера видит
js/core/paperSurface.js       микрорельеф бумаги (карта нормалей)
js/core/backdrop.js           фон сцены — для страницы и для снимка
js/loaders/                загрузка модели и макета
js/data/order.js           данные заказа и умолчания текста
js/data/catalog.js         номенклатура → модель, картон → шероховатость
js/data/sanitize.js        проверка данных, пришедших извне
js/ui/                     панель управления, вкладки, развёртка, согласование
scripts/                   сборка, локальный сервер, пережатие карты освещения
vendor/draco/              распаковщик сжатых 3D-моделей (своя копия)
assets/                    модели, макеты, карта освещения, иконки
docs/integration.md        для IT-отдела: развёртывание и подключение к Битриксу
tools/illustrator/         отдельный скрипт цветопробы, к сайту не относится
```
