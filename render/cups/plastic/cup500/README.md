# Стакан 500 мл, чертёж 252214 — параметрическая модель для Blender

Модель строится по одному JSON-конфигу: 2D-профиль сечения вращается в тело,
к нему добавляются четыре ребра расстыковки и выпуклое клеймо дна. Стенка
получает две аналитические UV-развёртки — геометрическую (кольцевой сектор) и
печатное поле шелкографии (прямоугольный макет с полями и зазором на стыке).

Источник размеров — чертёж `Cup 500ml-004-252214-new part 2D-Rev06-20260121.pdf`
(SJ S&P Mfg, TOOL NO. 252214, Rev06). Чертёж векторный, выполнен 1:1
(A3, 1190.55×841.89 pt, 1 pt = 25.4/72 мм), поэтому координаты контура и клейма
сняты из путей PDF, а проставленные размеры использованы как перекрёстная сверка.

## 1. Запуск

```bash
cd cup500
py -3.11 -m pytest -q
```

```bash
blender -b -P run.py -- --verify
```

```bash
blender -b -P run.py -- --render
```

```bash
blender -b -P run.py -- --export
```

Из работающего Blender через MCP передаётся только запускающий вызов:

```python
import sys, importlib
sys.path.insert(0, "D:/Cups_Soft/3D_plast/cup500")
import run; importlib.reload(run)
run.main(["--verify"])
```

Порядок `sys.path` и `reload` обязателен, иначе Blender отдаст закэшированный
модуль. Подмодули из `src/` перезагружаются внутри `run._reload_src()`.

Коды возврата: `0` — всё сошлось, `2` — ошибка конфига, `3` — `pass: false`.

Разовая подготовка данных клейма (нужен PyMuPDF, самой модели он не нужен):

```bash
py -3.11 extract_marking.py "../<файл чертежа>.pdf" .
```

## 3. Формула развёртки

Боковая стенка — усечённый конус, поверхность развёртываемая, поэтому её точная
развёртка на плоскость — кольцевой сектор без искажения.

Для пояса конуса с бОльшим радиусом `r1`, меньшим `r2` и высотой `h`:

```
l      = sqrt(h² + (r1 − r2)²)                 образующая пояса
β      = atan((r1 − r2) / h)                   полуугол конуса
α      = 360° · (r1 − r2) / l = 360° · sin β   угол сектора
R_out  = l · r1 / (r1 − r2)                    наружный радиус сектора
R_in   = R_out − l                             внутренний радиус сектора
s      = r / sin β                             расстояние по образующей от вершины
```

Из `α = 360°·sin β` следует, что угол сектора зависит только от угла конуса и не
меняется от того, какой кусок борта взят.

### 3.1 Слой `UVMap` — геометрическая развёртка

`uv.mode = "cone_sector"`:

```
ψ   = (θ − θ_шва) mod 2π
φ   = α · ψ / 2π − α/2
u   = 0.5 + (s / R_out) · sin φ / 2
v   = 0.5 + (s / R_out) · cos φ / 2
```

Затем остров **равномерно** (один масштаб + сдвиг, без анизотропии) сажается в
свой прямоугольник 0..1; коэффициенты печатаются в `out/verify.json` в поле
`uv_fit.wall`: `U = u·scale + dx`, `V = v·scale + dy`.

Обратный переход для авторинга прямо в UV:

```
u = (U − dx) / scale                 v = (V − dy) / scale
k = hypot(u − 0.5, v − 0.5)          s = 2·k·R_out
φ = atan2(u − 0.5, v − 0.5)          ψ = 2π·(φ + α/2)/α
```

| Пояс | z, мм | r, мм | α | R_in, мм | R_out, мм |
| --- | --- | --- | --- | --- | --- |
| `full` (по умолчанию) | 0 … 134.320 | 28.340 … 41.711 | **35.661°** | **286.09** | **421.08** |
| `visible` | 6.900 … 133.443 | 29.027 … 41.624 | **35.661°** | **293.03** | **420.19** |

Контроль: `α·R_out = 261.53 мм` равно `2π·41.624`.

### 3.2 Слой `UVPrint` — печатное поле шелкографии

Макет отдаётся прямоугольником, поэтому у него отдельный UV-слой. По вертикали
поле идёт по образующей от нижнего поля до верхнего, по горизонтали занимает всю
окружность за вычетом зазора на стыке. Зазор задаётся отдельно снизу и сверху —
на конусе он физически разный:

```
v    = (s − s_низ) / (s_верх − s_низ)
gap  = gap_низ + (gap_верх − gap_низ) · v          мм
half = gap / (2 · r(v))                            радианы
u    = (ψ − half) / (2π − 2·half)
```

За пределами поля `u` выходит за 0..1; текстура подключена с обрезкой (`CLIP`) и
смешивается с цветом материала по альфе, поэтому в зазоре запечатки нет, а цвет
остаётся молочным. Требование «все острова внутри 0..1» относится к `UVMap`, и
оно выполняется.

Текущее поле (`print` в конфиге: верх 15, низ 20, зазор 10 снизу и 20 сверху):

| | низ | середина | верх |
| --- | --- | --- | --- |
| z, мм | 20.00 | 70.15 | 120.30 |
| радиус, мм | 30.331 | 35.323 | 40.316 |
| окружность, мм | 190.58 | 221.94 | 253.31 |
| зазор, мм | 10.0 | 15.0 | 20.0 |
| **ширина печати, мм** | **180.58** | **206.94** | **233.31** |

Высота поля по образующей **100.80 мм**, пропорция макета **206.94 : 100.80 =
2.053 : 1**.

> Ваша оценка «длина центральной линии ≈ 220 мм» и «зазор 10 снизу, 20 сверху»
> друг с другом не сходятся: при таких зазорах центральная линия выходит
> **206.9 мм**, а 220 мм получаются при почти нулевом зазоре (≈1.9 мм по всей
> высоте). Что из двух главнее — решается одним числом в конфиге: зазоры ведут,
> длина центральной линии считается и печатается в отчёте.

## 5. Клеймо дна

`extract_marking.py` вытаскивает знаки из векторов нижнего вида и складывает в
`params/bottom_marking.json` — 51 замкнутая петля, 1595 точек, кольцо
r = 16.34…25.98 мм. `build.py` делает из них 2D-кривую Blender: заливка с
дырками в буквах — штатное поведение кривой, поэтому триангулировать с
отверстиями вручную не нужно.

Рельеф **выпуклый, 0.25 мм** наружу от плоскости поднутрения дна z = 1.500
(значение не проставлено на чертеже, принято по указанию заказчика). Площадь
знаков 60.70 мм², объём рельефа 15.17 мм³.

Ключ `marking.mirror_x = true`: нижний вид чертежа — взгляд на дно снаружи, и
при взгляде снизу экранное «вправо» соответствует −X модели. Проверено
ортогональным рендером с явно заданной матрицей камеры.

`marking.raised = false` (углублённая гравировка) требует булевой операции и
пока не поддержан — конфиг падает с понятным сообщением, а не строит молча
неверное.

## 6. Материал

Разобран по референсным фото заказчика (`ref/`), а не подобран на глаз. Что там
видно:

* сквозь неокрашенную стенку **видно руку и предметы за стаканом**, размыто, но
  отчётливо — пропускание высокое, а «молочность» даёт рассеяние, а не пигмент;
* неокрашенный PP **матовый**: резкого блика нет, только широкая мягкая засветка;
* краска шелкографии наоборот **глянцевая и укрывистая** — на чёрной заливке
  видны резкие вертикальные блики;
* светлые клетки на шахматном референсе — это не белая краска, а голый стакан:
  сквозь них видно пальцы.

Отсюда материал `Cup_PP` — не константа, а две зоны, которые переключаются по
альфе макета:

| Вход Principled | Подложка (нет краски) | Краска (альфа = 1) |
| --- | --- | --- |
| Base Color | 0.880 / 0.892 / 0.900 | цвет макета |
| Roughness | **0.45** (матовый фрост) | **0.10** (глянец) |
| Transmission Weight | **0.95** | **0.0** (укрывистая) |
| IOR | 1.49 | 1.49 |
| Thin Wall | **вкл** | вкл |
| Metallic | 0 | 0 |

`Thin Wall` включён потому, что стенка 0.5 мм — тонкая оболочка: без него
преломление считалось бы как в толстом стекле и стакан выглядел бы линзой.

**Альфа в макете обязательна.** Материал берёт по ней маску краски; если файл
без альфа-канала, вся площадь поля будет считаться запечатанной.

### Свет и студия

Без пола блик на глянцевой краске взяться неоткуда: стенка конуса наклонена
наружу на 5.685°, её зеркальное направление уходит **вниз**, и на референсных
фото яркая полоса на краске — это отражение светлого стола. Поэтому `--render`
ставит студийный пол (`render.studio`) и три источника, ключевой из которых —
узкий высокий прямоугольник, дающий вертикальный блик, как отражение окна.

Камера опущена ближе к середине стакана (elev ≈ 15°), как на референсах: при
высокой камере зеркальное направление уходит под пол и глянец не читается.

Пол и свет живут в коллекции `CUP500`; `render.studio.enabled = false`
выключает пол, если нужен чистый вырез на фоне.

## 7. Ручная проверка UV

Две тестовые сетки, обе генерируются из `out/verify.json` и всегда согласованы с
последней сборкой:

```bash
py -3.11 make_test_grid.py print .     # out/test_grid_print.png, 4096x1995
py -3.11 make_test_grid.py sector .    # out/test_grid_sector.png, 4096x4096
```

`test_grid_print.png` — прямоугольный макет **RGBA** 206.9 × 100.8 мм, шаг 10 мм,
штрих 0.30 мм (каждый пятый красный, 0.60 мм), плюс сплошная плашка 40×30 мм для
проверки укрывистости и глянца краски. Между линиями альфа нулевая, поэтому там
остаётся голый матовый PP — как светлые клетки на референсном шахматном стакане.
Подложить в `shader.maps.design`, запустить `--render` и
проверить на `out/preview.png`: горизонтальные линии должны идти ровными
кольцами без спирали, вертикальные — прямыми образующими, поле должно начинаться
на 20 мм от опорной плоскости и кончаться за 15 мм до кромки.

Ячейка 10×10 мм квадратная на центральной линии; выше она шире, ниже уже —
ровно на столько, на сколько меняется окружность конуса. Это и есть то
искажение, которое даёт печать прямоугольного макета на конус, и именно его
макет должен показывать.

`test_grid_sector.png` — кольцевой сектор под слой `UVMap` для случая, когда
макет готовится как настоящая развёртка конуса. Замеренное `uv_max_stretch` для
`UVMap` — **1.0001**, плотность текселя при 4096 — **15.8 px/мм**.

## 8. Раскладка UVMap

Три острова, все внутри 0..1, без перекрытий, зазор 388 px при 4096:

| Остров | Что входит | Прямоугольник (u0, v0, u1, v1) |
| --- | --- | --- |
| `wall` | наружный конус z 0…134.320 | 0.00, 0.26, 1.00, 1.00 |
| `rim` | венчик от касательной R0.40 до касательной R0.95 | 0.00, 0.00, 0.62, 0.25 |
| `body` | наружное дно, клеймо, рёбра, внутренняя стенка и дно | 0.63, 0.00, 1.00, 0.25 |

Шов один, по азимуту `uv.seam_azimuth_deg` (180°, задняя сторона). Граням на шве
азимут раскрывается за 2π, иначе грань растянулась бы на весь остров.

В остров стенки попадают только вершины, реально лежащие на наружном конусе:
у рёбер и клейма ближайшая точка профиля иногда оказывается точкой борта, и
классификация «по ближайшей точке» без этой проверки завышала бы `uv_max_stretch`.

## 10. Отступления от ТЗ и почему

| Пункт ТЗ | Как сделано | Почему |
| --- | --- | --- |
| `scale_length = 0.001` | `mesh.unit_scale_length = 1.0` | геометрия в метрах; при 0.001 Blender показывал бы 135.3 мм как 0.135 мм |
| `bpy.ops.mesh.spin` | Screw-модификатор через depsgraph | ТЗ допускает «Screw / spin»; не нужен ни режим правки, ни подмена контекста |
| Blender 4.2 LTS | фактическая сборка 5.2.0 LTS, Python 3.13 | что установлено |
| Cycles | `render.engine = "BLENDER_EEVEE"` | Cycles в этой сборке не зарегистрирован |
| «радиусы меньше половины толщины стенки» | проверяется, что скругление помещается в угол | буквальное правило отвергло бы сам чертёж: R0.95 при стенке 0.50 |
| `shade_smooth_by_angle` | острые рёбра расставляются через bmesh | оператор требует контекста 3D-вида и не проходит poll() из MCP |
| одна UV-развёртка | два слоя: `UVMap` и `UVPrint` | макет шелкографии прямоугольный и с зазором, геометрическая развёртка — сектор; в одном слое эти два требования несовместимы |
| дерево файлов п.4.1 | добавлены `make_test_grid.py`, `extract_marking.py`, `params/bottom_marking.json` | генератор тестовых сеток и разовое извлечение клейма из PDF |

При `--render` объекты вне коллекции `CUP500` прячутся только на время кадра и
возвращаются как были; фон берётся из отдельного мира `CUP500_World`.

## 11. Структура

```
cup500/
  params/cup_500ml.json       единственный источник размеров, у каждого ключа _src
  params/bottom_marking.json  петли клейма, генерируются extract_marking.py
  src/profile.py              профиль, сечение ребра, объёмы, валидация (чистый Python)
  src/unwrap.py               конический сектор и печатное поле (чистый Python)
  src/build.py                тело вращения, рёбра, клеймо, UV, материал (bpy)
  src/verify.py               замеры -> out/verify.json (bpy)
  src/render.py               камера, свет, preview.png и uv_layout.png (bpy)
  run.py                      оркестратор
  make_test_grid.py           тестовые сетки print / sector (stdlib)
  extract_marking.py          разовое извлечение клейма из PDF (нужен PyMuPDF)
  tests/                      pytest, без bpy
  out/                        verify.json, превью, развёртка, glb, obj, blend
```

В `src/profile.py` и `src/unwrap.py` нет ни одного импорта `bpy`. Числовых
литералов размеров в коде геометрии нет — всё приходит из JSON.
