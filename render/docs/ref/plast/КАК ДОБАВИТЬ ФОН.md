# Как добавить новый фон

Фон — это один файл `mockup/sets/<имя>.json`. Больше ничего заводить не нужно:
раннер сам подхватывает всё, что лежит в этой папке, и имя файла становится
именем фона. Ни общий конфиг, ни код, ни существующие кадры при этом не
меняются.

Проверить, что фон появился:

```bat
blender -b --factory-startup -P mockup\run.py -- --list
```

Фоны бывают трёх видов, и снаружи разницы нет — все снимаются одной командой.
Новый `source: authored` используется для S07/S12/S14: геометрия окружения
строится `mockup/bk/authored.py`, а камера и положение стакана задаются JSON.
Ключи этого типа описаны в [реестре фонов](../mockup/sets/README.md).
Для существующего типа достаточно нового JSON; новый способ построения
окружения требует соответствующего кода.

---

## Вид 1. Готовая сцена — `source: blend`

Берём чужую сцену целиком: интерьер, стол, воду, свет. Стакан встаёт на место
убранного «героя» и наследует освещение сцены.

Сцены лежат в `mockup/scenes/4.blend`. Файл самодостаточен: внешних связанных
библиотек в нём нет, поэтому его можно перемещать вместе с проектом.

### Шаг 1. Узнать имена внутри файла

```bat
blender -b mockup\scenes\4.blend --python-expr "import bpy;[print(s.name,'|',[o.name for o in s.objects if o.type=='CAMERA']) for s in bpy.data.scenes]"
```

Нужны три вещи: имя сцены, имя камеры и имя объекта-героя — того предмета,
вместо которого встанет стакан.

### Шаг 2. Положить файл фона

`mockup/sets/kitchen.json`:

```json
{
  "title": "Кухонный стол",
  "source": "blend",
  "scene": "Kitchen Morning",
  "camera": "Camera",
  "hero": ["Bottle", "Bottle_Label", "Bottle_Cap"],
  "fit_ref": ["Bottle"],
  "height_scale": 1.0,
  "offset": [0.0, 0.0, 0.0],
  "rotation_deg": [0, 0, 0],
  "samples": 450,
  "resolution": 1600
}
```

| Ключ | Смысл |
|---|---|
| `scene`, `camera` | имена внутри `4.blend` |
| `hero` | что убрать из сцены: сам предмет, его этикетка, крышка, всё что от него осталось |
| `fit_ref` | по какому объекту считается посадка. Обычно сам герой. Габарит снимается **до** удаления |
| `height_scale` | во сколько раз стакан выше героя. 1.0 — ростом с него |
| `offset` | сдвиг в метрах, если стакан сел не туда |
| `rotation_deg` | поворот стакана в сцене, три оси |
| `hide_from_camera` | необязательный список: что спрятать от камеры, оставив светить сцену |

### Шаг 3. Посмотреть черновик и поправить посадку

```bat
blender -b --factory-startup -P mockup\run.py -- --set kitchen --render --samples 64 --resolution 700
```

Отчёт в консоли покажет, что получилось:

```
### kitchen: стакан 500 мл, сцена 'Kitchen Morning', камера Camera
###   герой убран: 3 об., высота героя 190 мм -> стакан 135.3 мм x0.712, посадка [0.02, -0.05, 0.0]
```

Что править, если не сошлось:

- стакан слишком мелкий или крупный — `height_scale`;
- стоит не на том месте — `offset`, по одной оси за раз;
- печать смотрит не в камеру — `rotation_deg` по Z;
- в кадр вылезла подсветка, которую раньше закрывал герой — добавьте её в
  `hide_from_camera`: она останется светить, но исчезнет из кадра;
- от героя остался хвост (тень-карточка, отражатель, подставка) — допишите его
  в `hero`.

Габарит героя снимается до удаления, поэтому убирать в `hero` можно смело: на
посадку это не повлияет, пока в `fit_ref` остаётся то, по чему меряем.

## Вид 2. Свой фотобокс — `source: greybox`

Циклорама, свет и камеры строятся кодом под высоту стакана. Готовая сцена не
нужна, и 410, 500 и 650 мл занимают в кадре одинаковую долю.

Самый быстрый путь — скопировать `mockup/sets/studio.json` и поменять числа.
`mockup/sets/studio_dark.json`:

```json
{
  "title": "Тёмный фотобокс",
  "source": "greybox",
  "camera": "catalog",
  "cameras": { "catalog": 8, "print": 2 },
  "gray_linear": 0.035,
  "world_strength": 0.02,
  "exposure": 0.0,
  "key_w_at_135mm": 18.0,
  "fill_w_at_135mm": 1.2,
  "rim_w_at_135mm": 14.0,
  "samples": 450,
  "resolution": 1600
}
```

| Ключ | Смысл |
|---|---|
| `gray_linear` | яркость циклорамы, линейная. 0.14 — светло-серый, 0.03 — почти чёрный |
| `world_strength` | общая подсветка, работает как очень мягкий заполняющий |
| `key_w_at_135mm` | рисующий слева-спереди |
| `fill_w_at_135mm` | заполняющий справа. Чем меньше, тем контрастнее кадр |
| `rim_w_at_135mm` | контурный сверху-сзади, рисует светлую кромку венчика |
| `cameras` | имя камеры → наклон вниз в градусах |
| `camera` | какая из них снимает по умолчанию |
| `distance_in_heights` | дистанция в высотах стакана, по умолчанию 3.75 |
| `lens_mm`, `sensor_mm` | оптика, по умолчанию 90 мм на 36 мм |
| `exposure`, `view_transform`, `look` | цветокоррекция кадра |

Мощности заданы для стакана 135 мм и пересчитываются по квадрату высоты.
Поэтому одни и те же числа дают одинаковую экспозицию на всех трёх объёмах —
менять их под объём не нужно.

Камеры считают дистанцию с поправкой на наклон: 8 градусов каталога и
2 градуса печати дают одинаковый масштаб изделия в кадре.

## Что проверить в любом фоне

**За стаканом не должно быть контрастных границ.** Материал изделия
полупрозрачный по построению: тёмная грань декорации, оказавшаяся прямо за
стаканом, просвечивает сквозь стенку и читается как предмет внутри него. На
чистом кадре без печати это особенно заметно. Ставьте крупные формы сбоку и
выше, оставляя за изделием ровный участок фона.

## Чего в фоне быть не должно

- **Своего материала стакана.** Материал один на проект, он в
  `mockup/params/shots.json`. Кадр, снятый другим материалом, не сравним с
  остальными.
- **Своей геометрии.** Стакан приходит из `product/`, фон его не переделывает.
- **Абсолютных путей.** Всё относительно папки `mockup`.

Печать фон может переопределить — блоком `print` внутри своего файла, если
конкретно этому кадру нужен другой макет. Общие настройки печати он при этом не
трогает.

## Проверка перед сдачей

```bat
blender -b --factory-startup -P mockup\run.py -- --set kitchen --render
```

Смотрите в отчёте: нет ли строк `WARN`, убралось ли столько объектов героя,
сколько ожидали, и какое искажение у макета. Рядом с кадром ложится `.json` с
теми же числами — по нему кадр восстанавливается позже.
