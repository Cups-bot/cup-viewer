## 1. Цель

Локальный сервис для фотореалистичных мокапов **любого стакана линейки**:
17 бумажных артикулов (плюс три EM с вафлей картой нормалей) и три пластиковых.
Сотрудник в браузере выбирает сцену, ставит в неё один или несколько стаканов,
кладёт на каждый макет, подбирает ракурс и расстановку в лёгком 3D-превью и
отправляет в очередь. Считает Blender Cycles. На выходе кадр, сцена `.blend` и отчёт.

Сейчас всё это разнесено по трём проектам, и ни один не умеет всего:

| проект | что умеет | чего не умеет |
|---|---|---|
| `3D_plast` | 8 сцен, очередь, панель, материал PP, печать rect/cone, одинаковое качество кадров | только 3 пластиковых стакана, один стакан в кадре, ракурс только правкой JSON |
| `3D_Cups` | 20 моделей бумажных стаканов, макет листом A4 со сдвигом, конгрев, GLB | только своя серая студия, работа руками в Blender |
| `cup-viewer` | движок three.js, GLB всех моделей, фото-сцена «в интерьере», стиль colorcups, Lottie | не фотореализм: рендер в браузере |

3DCupRender соединяет их: сцены и раннер берутся из пластика, модели и наложение
макета из бумаги, превью, стиль и анимации из просмотрщика.

## 2. Что уже собрано

Всё в `source/`, подробно в [ИСТОЧНИКИ.md](ИСТОЧНИКИ.md). Копии, оригиналы не
тронуты. Раннер пластика запускается прямо из копии (`--list` видит 8 фонов).

## 3. Пользователь и окружение

- [есть] Windows 11, Blender 5.2, Cycles на GPU (OptiX). Видеокарта одна, поэтому
  задания считаются строго по одному.
- [решено 2026-09-25] Пока сервис работает только на этом ПК: слушает `127.0.0.1`
  и запускается двойным щелчком по `ПАНЕЛЬ.bat`, как в пластике. Интернет не нужен,
  вход по паролю не нужен.
- [решено 2026-09-25] Позже рендер может переехать на отдельный сервер. Поэтому
  это закладывается сразу:
  - **задание самодостаточно**: папка задания содержит `job.json` и копии всех
    макетов, пути только относительные. Такую папку можно отправить на другую
    машину и посчитать там;
  - **очередь и исполнитель рендера разделены**: сервер панели ставит задания в
    очередь, а отдельный исполнитель (сейчас локальный процесс Blender) их забирает
    и возвращает результат. Второй исполнитель на сервере добавляется без
    переделки панели;
  - каталог стаканов, сцены и модели версионируются (хэш в отчёте), чтобы сервер
    мог проверить, что у него те же файлы.

## 4. Основной сценарий

1. **Сцена.** Карточки 8 сцен с эталонным кадром (эталоны уже лежат в
   `source/plast/mockup/out/эталоны_сцен`).
2. **Стаканы.** Пикер как в cup-viewer: силуэты, группы «однослойные / двухслойные /
   вафельные / пластик», объём. «Добавить стакан» ставит в сцену ещё один. Быстрые
   кнопки: «Пара» (тот же стакан, второй развёрнут) и «Два объёма» (соседние
   объёмы одной серии рядом).
3. **Макет.** На каждый стакан свой или общий, PDF / JPG / PNG. Для бумаги это
   полный лист развёртки, для пластика поле 200×85 / 110 / 150 мм или полная
   запечатка. Превью развёртки с сеткой печатного поля.
4. **Ракурс и расстановка** в лёгком вьюере (§6): стаканы двигаются по полу и
   поворачиваются вокруг оси, камера выбирается из пресетов сцены, видна рамка кадра.
5. **Черновик.** Кнопка «Проверить в Blender» даёт быстрый кадр 700 px / 64 сэмпла
   за 10–20 секунд. Черновик считается вне очереди.
6. **В очередь** в рабочем или финальном качестве. Заданий можно поставить много
   и уйти.
7. **Галерея.** Кадры с подписями (сцена, стаканы, макеты, качество, время).
   Кадр можно открыть, скачать или повторить с изменениями.

## 5. Функциональные требования

### 5.1 Единый каталог стаканов

- [предлагаю] Один файл `catalog/cups.json` на основе `models.json` просмотрщика:
  там уже есть 19 моделей, размеры, развёртки и азимут шва. Добавляются поля для
  Blender: путь к `.blend`, что из него брать, способ наложения макета, материалы.
- [предлагаю] Идентификаторы как в просмотрщике: `HB80-280`, `DW90-430`,
  `EM80-280`, `BM90-410 / 500 / 655`. У пластика в раннере сейчас `410 / 500 / 650`,
  эти имена остаются алиасами.
- Стаканы устроены по-разному:
  - **бумажный** — две сетки (`Cup_Wall`, `Cup_Bottom`) под пустышкой
    `CUPS_Product` в коллекции `CUPS_Mockup`, свои материалы
    `Paper_Print / Paper_Inner / Paper_Edge`, макет листом A4 со сдвигом;
  - **пластиковый** — один меш `Cup_500ml`, общий материал PP из `shots.json`,
    печать по слоям `UVPrint` / `UVMap`.

  Поэтому раннеру нужен **адаптер на каждый тип стакана** (`paper`, `plastic`).
  Адаптер отвечает за импорт, материал и макет, а сцена о типе стакана не знает.
  Новый тип (например PET) добавляется ещё одним адаптером.
- [решено 2026-09-25] Вафельные EM по умолчанию берутся с вафлей, вылепленной в
  сетке (`EMxx-xxx`). В панели у стакана есть переключатель версии: «вафля в
  сетке» или «карта нормалей» (`-NM`, легче, конгрев заменяемый). EM90-530 входит
  в каталог, хотя в просмотрщике его нет.
- [решено 2026-09-25] Материалы бумаги в рендере — все четыре, как в
  просмотрщике: мелованный, немелованный, soft-touch, крафт (печать без белил, по
  бурому картону). В Blender-аддоне сейчас один набор `Paper_*`, поэтому четыре
  материала нужно сделать и откалибровать в Cycles. Калибровка по фотографиям
  реальных стаканов, как это было сделано для PP по `ref/`.
- [решено 2026-09-25] Опорные фото для калибровки берутся из отзывов MyCups
  (сайт mycups.ru и Яндекс Карты). Разбор фото — в `docs/ref/отзывы_mycups.md`.
- [решено и сделано 2026-09-25] **Прозрачный PET** — три стакана Polyer Ø95, у
  MyCups шифры по объёму до края: PG95-400 (300 мл), PG95-520 (400 мл), PG95-600
  (500 мл). Профили взяты из векторных шаблонов MyCups, для 600 — из каталога
  Polyer. Печать только с двух сторон, А и Б. Модели и сборщик лежат в `cups/pet/`.
  В раннере PET уже снимается во всех сценах со своим материалом (`material: own`).
  Разбор — `docs/ref/PET_Polyer_400.md`.

### 5.2 Сцены

- [есть] Сцены из пластика:
  - фотобокс `studio`, строится кодом;
  - `living`, `water`, `podium`, `spotlight` — готовые сцены из `4.blend`;
  - авторские `window`, `cream`, `ice`, строятся кодом.
- [решено 2026-09-25] `ice` не используем вообще: фон выключен (`"enabled": false`),
  файлы оставлены. В работе 7 сцен.
- Новая сцена добавляется одним JSON в `sets/`, код не трогается. Это правило
  пластика сохраняется.
- **Масштаб.** Сейчас в сценах из `4.blend` стакан подгоняется под убранного
  «героя». По отчётам эталонов в `water` он увеличен в 22,5 раза, в `podium` в 1,8,
  в `spotlight` уменьшен до 0,83. Для одного стакана это нормально, но для набора
  разных объёмов так нельзя: стакан на 120 мл встанет ростом со стакан на 500 мл.
  [решено 2026-09-25] Масштаб сцены считается один раз по эталонному стакану
  (500 мл, 135 мм) и применяется ко всем стаканам кадра. Размеры стаканов
  относительно друг друга честные, 1:1.
- Отсюда следствие: маленький стакан (HB62-120, 63 мм) в сцене, рассчитанной на
  135-мм героя, выйдет мелким. [решено 2026-09-25] Камера подстраивается под
  группу: направление сохраняется, но камера приближается (дистанция или
  фокусное), чтобы группа занимала задуманную долю кадра. Эта доля задаётся в
  файле сцены по эталонному кадру. Приближение ограничено, чтобы не вылезли края
  декораций и не развалилась глубина резкости.
- [решено 2026-09-25, этап 3, выбор за мной — владелец посмотрит] Приближение —
  **кадрированием**, а не подъездом камеры: камера ракурса стоит на месте,
  фокусное и сдвиг объектива выбирают окно кадра (0,55–1,25 от кадра фона для
  одного стакана, шире — для пары). Диаметр зрачка сохраняется, поэтому размытие
  фона — ровно вырез из размытия кадра фона. Зачем: превью (§6) показывает снимок
  фона из той же камеры, и любой вырез из него совпадает с рендером. При
  подъезде камеры фон смещается параллаксом, и превью врало бы. Кадр эталона
  500 мл не изменился (сверка: 4 пикселя шума из 160 тысяч). Прежний подъезд
  остался переключателем `camera_fit_mode: dolly`, превью с ним не совпадает.
- **Площадка.** [сделано, этап 3] Место, где можно ставить стаканы, — не
  многоугольник, а карта площадки из Blender (`web/scenes/<фон>/scene.json`):
  сетка ±32 см с шагом 4 мм в осях сцены, где опора (луч вниз) и где помеха над
  полом (луч вверх). Превью по ней ставит стакан на опору и подсвечивает место,
  которое не годится; рендер проверяет то же лучами по самой сцене
  (`group.spot_ok`). Максимум стаканов — `max_cups`.
- [решено 2026-09-25] Во всех сценах не больше двух стаканов; в `water`, `podium` и
  `cream` — один (`max_cups: 1`, этап 2).
- [решено 2026-09-25] **living:** стакан стоял в 4 мм от переднего края тумбы.
  Теперь он сдвинут на 6 см вглубь (до края около 5 см), камера поднята на 7°
  вокруг стакана, фокус переведён на стакан. Для этого в раннер добавлены ключи
  сцены `camera_orbit_deg` и `focus: "cup"`. Попутно выяснилось, что у камер в
  `4.blend` есть анимация, которая при рендере возвращала камеру на место; при
  повороте камеры анимация теперь снимается. Вариант с подъёмом на 12° снят для
  сравнения, выбор за вами.
- [решено 2026-09-25] Кафе из cup-viewer не нужно. Сцены S01–S16 — после v1.

### 5.3 Макеты

- **Бумага:** PDF / JPG / PNG полного листа шаблона (A4, у EM90-530 297×235 мм).
  Страница PDF, dpi, скрытие техслоёв (Masks / Info / setka), сдвиг X/Y и масштаб
  привязки уже есть в аддоне `cup_mockup`. В панели они станут полями.
- **Пластик:** PNG поля печати (`rect`: 200×85 / 110 / 150 мм по объёму) или полная
  запечатка по сектору (`cone`). Шаблоны лежат в `mockup/art`.
- **Конгрев** (бумага): чёрно-белый лист и глубина в мм, уже есть в аддоне.
  [решено 2026-09-25] В панели с первой версии.
- Проверки при загрузке: формат листа совпадает с шаблоном стакана (±2 мм),
  разрешение на печатном поле не ниже 300 dpi. Это предупреждения, не запреты.
- Исходник макета не меняется. В задание пишутся путь к нему и хэш.
- Превью в лёгком вьюере показывает тот же макет. PDF растеризуется pdf.js, он уже
  лежит в `vendor`.

### 5.4 Несколько стаканов в сцене

- [решено 2026-09-25, уточнено] Один или два стакана (в `water`, `podium`, `cream` один), оба стоят
  на полу. У каждого своя модель, макет, материал, положение на площадке в мм и
  поворот вокруг оси в градусах. Наклонных, лежащих стаканов и стопок в первой
  версии нет. Раньше было записано «до 4», это отменено.
- Один стакан — «главный»: на нём фокус (глубина резкости), по нему кадрирование.
- Быстрые компоновки:
  - [решено 2026-09-25] Стаканы стоят **в одну линию** (не друг за другом), пара —
    по центру прежнего места главного. Если в линию места нет (декор по бокам),
    второй смещается чуть вглубь;
  - **Пара** — копия главного рядом, развёрнута на 150°, чтобы была видна другая
    сторона дизайна;
  - **Два объёма** — соседние объёмы одной серии рядом, по росту;
  - **Свободно** — любой стакан добавляется вручную.
- Стаканы не пересекаются: минимальный зазор между стенками задаётся, по умолчанию
  3 мм. Поставить стакан за край площадки вьюер не даёт.
- Каждый стакан стоит на полу нижней точкой (Z = 0 площадки). Тени и отражения
  между стаканами считает Cycles.

### 5.5 Рендер и очередь

- Качества как в панели пластика:

  | качество | размер | сэмплы |
  |---|---|---|
  | черновик | 700 px | 64 |
  | рабочее | 1200 px | 200 |
  | финал | 1600 px | 512 (из файла фона) |

- [решено 2026-09-25] Форматы кадра: 1:1, 3:4 и 4:5. Длинная сторона по
  качеству (700 / 1200 / 1600 px), то есть финал 3:4 — это 1200×1600, а 4:5 —
  1280×1600. 16:9 и крупные размеры для печати пока не нужны.
- Формат влияет на превью: у каждого пресета камеры нужна подложка под каждый
  формат, либо одна подложка с запасом по краям, из которой вырезается нужный
  кадр. [решено, этап 3] Одна подложка с запасом ×1,6: вертикальный кадр
  срезает бока вокруг стакана, высота кадра та же (`run.py --frame 3:4`).
- Очередь: одно задание за раз. Черновики идут вне очереди. Есть «Стоп», снятие
  задания и перестановка.
- Прогресс: живой лог Blender, процент по сэмплам (`Sample N/M`), оценка
  оставшегося времени по истории похожих заданий.
- Каждое задание воспроизводимо. В отчёт пишется всё: версия каталога, сцена,
  камера, стаканы с положениями, пути и хэши макетов, материал, качество, время.
- Результат ложится в `out/<дата>_<сцена>_<стаканы>/`: `frame.png`, `scene.blend`
  (если включено), `job.json`, `report.json` и превью 480 px для галереи.

### 5.6 Галерея

- Лента кадров с фильтрами (сцена, стакан, дата, черновик или финал). Кадр
  открывается крупно, скачивается в PNG, `.blend` открывается в Blender.
- «Повторить» загружает задание обратно в редактор, «Сравнить» ставит два кадра рядом.

### 5.7 Панель: стиль colorcups.ru и Lottie

- [есть] Токены те же, что в cup-viewer и на colorcups.ru:
  - холст `#F5F5F7`, белые карточки, радиус 12–20 px;
  - действие — синяя кнопка-«пилюля» `#0071E3` (радиус 980 px);
  - системный шрифт (-apple-system, Segoe UI);
  - светлая и тёмная тема.

  Берутся из `source/viewer/css/app.css`.
- [есть] Lottie через lottie-web 5.13, как в просмотрщике. Уже есть пять анимаций:
  `pick` (выбор стакана), `print` (макет), `turn` (оборот), `wrap` (развёртка),
  `shot` (снимок). У каждой есть PNG-замена для режима без анимаций.
- [предлагаю] Где нужна анимация:
  - пустые состояния: нет стаканов, нет макета, пустая галерея;
  - ожидание рендера: Lottie, привязанная к проценту сэмплов;
  - «готово» и подсказки на шагах.

  Анимация не мешает работе: переходы 250–400 мс, при `prefers-reduced-motion`
  вместо неё статичная картинка.
- [решено 2026-09-25] Новые анимации («стакан появляется в сцене», «очередь»,
  «рендер идёт», «готово») рисую я, в стилистике colorcups.ru и cup-viewer: те же
  линии, толщины и цвета, что у пяти существующих, и та же PNG-замена для
  режима без анимаций.

## 6. Выбор ракурса: лёгкий вьюер

Задача: до долгого рендера увидеть будущий кадр и поправить его. Считать Cycles на
каждое движение мыши нельзя, поэтому превью работает в браузере. Совпадение с
итоговым кадром обеспечивает общий контракт камеры.

### Как устроено

[сделано, этап 3, 2026-09-25 — `web/preview/`, `engine/bk/frame.py`, `engine/bk/compose.py`]

- **Кадр — окно на плоскости изображения.** Окно — прямоугольник в тангенсах
  углов от оси камеры. Камера ракурса стоит на месте, а фокусное и сдвиг
  объектива выбирают окно: стакан другого роста, пара и формат кадра — это
  вырез. Превью и рендер считают окно одной и той же математикой
  (`frame.py` ↔ `fit.js`), и на сверке их окна совпадают до 0,02 %.
- **Подложка** — снимок фона без стакана и его тени из камеры ракурса, с
  запасом ×1,6 по каждой стороне (`<ракурс>.webp`, 2400 px). Кадр в превью —
  вырез из него; кадр шире запаса превью покажет с серыми краями и
  предупредит, рендер при этом верный.
- **Свет** — панорама из точки стакана (`env.hdr`, линейная) и главный источник
  сцены для тени; экспозиция — как у фона.
- **Стаканы** — модели из того же файла, что берёт рендер (`web/cups/*.glb`,
  Draco, 100–220 КБ), в осях Blender. Вся сцена превью живёт в осях Blender
  внутри группы, повёрнутой на −90° вокруг X, поэтому координаты из
  `scene.json` не переводятся.
- **Места стаканов** — в миллиметрах от места героя сцены: вправо по кадру фона
  и вглубь по полу. Высота опоры берётся из карты площадки (§5.2). Задание
  несёт `pos_mm` обоих стаканов, и рендер ставит их туда же.
- Что пользователь делает в превью (`web/preview/index.html`, основа шага
  «Ракурс и расстановка» панели):
  - тянет стакан по площадке; место, которое не годится (нет опоры, мешает
    декор, стаканы пересекаются), подсвечивается красным;
  - колесом над стаканом крутит его вокруг оси (5°, с Shift — 1°) или ползунком;
  - переключает ракурс и формат (1:1, 3:4, 4:5), видит рамку безопасной зоны;
  - «Пара», «Объём больше/меньше» раскладывают второй стакан так же, как
    раскладка рендера (в линию по центру прежнего места).
- **Сверка** (`web/preview/check.html` против масок
  `engine/tools/preview_mask.py`): 10 заданий — все 7 рабочих фонов, ракурсы, три
  формата, одиночные, пары, ручная расстановка. Приёмка — силуэты расходятся
  не больше чем на 2 px.
- Ракурсы фонов (`camera_presets`, облёт камеры фона вокруг центра эталона):

  | фон | ракурсы |
  |---|---|
  | living | как в сцене, сверху (+15°), ниже (−5°), справа (25°) |
  | water | как в сцене, сверху, ниже |
  | podium | как в сцене, сверху, слева |
  | spotlight | как в сцене, сверху, ниже, слева |
  | window | как в сцене, сверху, ниже |
  | cream | как в сцене, сверху, ниже, слева |
  | studio | каталог 8°, прямо 2°, сверху 25°, сверху 45° |

  Отброшены по пробным кадрам: края декораций (water слева и справа), пересвет
  прожектором (spotlight справа), размытый передний план (window и cream
  справа), тёмный угол стены (window слева).

### Насколько свободной делать камеру

| вариант | что даёт | цена |
|---|---|---|
| A. Камера сцены неподвижна, двигаются только стаканы | точное совпадение, дёшево | нельзя посмотреть сверху или снизу |
| B. Вариант A + 2–4 пресета камеры на сцену (каталог, сверху 30°, низкий, крупно), у каждого своя подложка | закрывает почти все задачи, совпадение точное | снять подложки для 8 сцен × пресеты |
| C. Свободное вращение камеры | полная свобода | нужна упрощённая геометрия сцены в браузере, превью перестаёт выглядеть как фото; для сцен из `4.blend` это тяжело |

[решено 2026-09-25] Вариант B для всех сцен. Вариант C только для `studio`: фон
там однородный и строится кодом, свободная камера ничего не ломает. Свободную
камеру в авторских сценах можно добавить позже, если понадобится. Последняя
проверка перед финалом — кнопка «Проверить в Blender».

Для `studio` свободная камера — это орбита вокруг группы стаканов: наклон от
−5° до 60°, любой азимут, дистанция и фокусное с ограничениями. Циклорама и свет
в Blender строятся заново под выбранную камеру, как и сейчас под высоту стакана.

[этап 3] Пока в `studio` четыре ракурса-пресета (8°, 2°, 25°, 45°). Фотобокс
теперь строится по эталону, а не под рост стакана: кадр — вырез, как везде.
Свободный наклон для `studio` — на этапе 4: подложка между пресетами —
ближайший снимок (фон однородный), рендер — точный угол.

## 7. Архитектура

```
Браузер: панель и лёгкий вьюер
  (ES-модули, three.js 0.160, lottie-web 5.13 — всё локально)
        │  HTTP/JSON, лог через SSE
Локальный сервер (Python, только стандартная библиотека, 127.0.0.1)
        │  собирает папку задания (job.json + макеты), держит очередь
Исполнитель рендера (сейчас локальный процесс; позже может быть сервер)
        │  забирает задания по одному, возвращает результат
Blender 5.2 -b --factory-startup -P engine/render.py -- --job job.json
        ├─ сцены: greybox / blend / authored     ← из пластика
        ├─ адаптеры стаканов: plastic / paper    ← раннер пластика и аддон cup_mockup
        └─ out/<задание>/frame.png, scene.blend, report.json
```

- [предлагаю] Сервер на стандартной библиотеке Python, как панель пластика:
  ничего не нужно ставить, работает без интернета.
- [предлагаю] Фронт на том же стеке, что cup-viewer (ES-модули, three.js 0.160,
  lottie-web). Так его движок, пикер и стили переиспользуются без переписывания.
  React и TypeScript не нужны.
- **Логика сборки одна.** Правило пластика сохраняется: панель только собирает
  `job.json`, а считает всё `render.py`. То же задание запускается из командной строки.
- Основа — раннер пластика (`run.py` и `bk/`). Что в нём меняется:
  1. стакан берётся из каталога через адаптер, а не из раздела `cups` в `shots.json`;
  2. в кадре список стаканов, а не один;
  3. масштаб сцены один на весь кадр (§5.2);
  4. камера — пресет из файла фона плюс поправки из задания.
- Бумажный аддон `cup_mockup` подключается как библиотека, без интерфейса: он
  строит или загружает стакан и накладывает макет.

### Формат задания

[работает с этапа 3: `engine/run.py --job задание.json`; превью пишет его само]

```json
{
  "set": "living",
  "camera": { "preset": "high", "frame": "4:5" },
  "samples": 200, "resolution": 1200,
  "cups": [
    { "id": "HB80-280", "board": "coated", "art": "макет.pdf", "page": 1,
      "rotate": 20, "pos_mm": [-49, 0] },
    { "id": "HB80-280", "board": "coated", "art": "макет.pdf", "page": 1,
      "rotate": 170, "pos_mm": [49, 0] }
  ]
}
```

- `pos_mm` — место дна в мм от места героя сцены: вправо по кадру фона, вглубь.
  Без `pos_mm` у второго стакана место подбирает раскладка (`layout`: `pair`,
  `side`). Высоту опоры рендер находит лучами.
- Кадр в задании не пишется: рендер выбирает его по тем же правилам, что превью
  (`frame.py` ↔ `fit.js`). Ручная подстройка кадра — этап 4.
- Пути к макетам — от файла задания: папку задания можно отдать на другую машину.

## 8. Нефункциональные требования

- Работает без интернета, ничего не ставится через pip. [?] Node нужен только для
  сборки фронта, как в cup-viewer. Или обходиться вообще без сборки?
- Качество рендера не хуже эталонов пластика: тот же материал PP, тот же свет, AgX.
  Эталонные кадры 8 сцен с 500 мл новый движок должен воспроизводить; сравнение по
  ΔE, как `render:check` в просмотрщике.
- Цвет макета важнее эффектности (правило просмотрщика §15).
- Исходные проекты не меняются. Заводские файлы и модели только читаются.
- Задания не теряются при закрытии браузера. После перезапуска сервера очередь
  восстанавливается из `out/queue.json`.
- Время: черновик не дольше 20 с (living сейчас — 22 с вместе с загрузкой сцены),
  финал одного стакана — как сейчас в пластике. Два стакана в кадре добавляют
  примерно 20–40 % к времени: больше преломлений и теней.
