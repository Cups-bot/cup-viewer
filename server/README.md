# Сервер CupViewer (этапы Г–Е)

API и сайт одним процессом: вход по почте и коду, токены, задания рендера,
файлы на 30 дней, оплата-заглушка, админка. Концепция —
`docs/CONCEPT-v2.md` (§3–§10). Всё работает на этом компьютере; выгрузка на
Timeweb — этап Ж.

## Запуск

Один раз — окружение (библиотеки из `requirements.txt`):

```bat
python -m venv server\.venv
server\.venv\Scripts\python -m pip install -r server\requirements.txt
```

Сервер (сайт и API на http://127.0.0.1:8000):

```bat
server\.venv\Scripts\python server\run.py
```

Исполнитель рендера — в соседнем окне; сам берёт задания и считает их Blender:

```bat
server\.venv\Scripts\python server\worker.py
```

Локально исполнитель считает черновики (профиль `draft`: 48–64 сэмпла,
800–1000 px) при любом выбранном размере — ноутбук не тянет полное качество.
На сервере с видеокартой: `set CV_WORKER_PROFILE=full`.

Код входа письмом пока не уходит — он печатается в консоли сервера:
`=== Код входа для name@mail.ru: 123456 ===`.

## Что где

| файл | что |
|---|---|
| `app/main.py` | приложение: API, раздача сайта (только `index.html`, `admin.html`, `dist/`, `css/`, `js/`, `assets/`, `catalog/`, `vendor/`; пути с `..` и скрытые файлы — 404), заголовки безопасности, уборка раз в 10 минут |
| `app/auth.py` | вход: код 6 цифр на 10 минут, 5 попыток (неверная засчитывается и при ошибке); одноразовые почты не принимаются; 3 приветственных токена на 30 дней |
| `app/tokens.py` | журнал токенов: кошельки paid (купленные) и welcome (приветственные); кадр — целиком из одного |
| `app/jobs.py` | задания: резерв токенов, очередь (купленные раньше, у бесплатных одно задание), место и ожидаемое время, кадры, «Убрать знак» (только купленными токенами), повтор, отмена; API исполнителя |
| `app/admin.py` | пакеты токенов (тестовая оплата), админка: пользователи, начисления, очередь, платежи |
| `app/watermark.py` | знак на кадре за приветственный токен и миниатюры галереи |
| `worker.py` | исполнитель: `render/engine/run.py --job`, пониженный приоритет, 4 потока, пульс каждые 30 с |
| `data/` | база SQLite, макеты, кадры, ключ исполнителя (`worker.key`) — не в git |

## Настройки (переменные окружения)

| переменная | по умолчанию | что |
|---|---|---|
| `CV_PORT`, `CV_HOST` | 8000, 127.0.0.1 | адрес сервера |
| `CV_DATA` | `server/data` | база и файлы |
| `CV_ADMINS` | danilkakhudia@gmail.com | почты администраторов через запятую |
| `CV_SERVER` | http://127.0.0.1:8000/ | куда ходит исполнитель |
| `CV_WORKER_PROFILE` | draft | `draft` или `full` |
| `CV_BLENDER`, `CV_THREADS` | Blender 5.2, 4 | Blender исполнителя |

Цены, пакеты, сроки — `app/config.py` (`PRICES`, `PACKS`, `WELCOME_*`, `RETENTION_DAYS`).

## Проверки

```bat
server\.venv\Scripts\python -m unittest server.tests.test_flow -v
node tests\account\e2e.mjs            :: кабинет глазами человека (исполнитель — запросами)
node tests\account\e2e.mjs --real     :: то же с настоящим исполнителем и Blender (черновик)
```

`test_flow` поднимает сервер на временной базе и проходит вход, резерв и
возврат токенов, очередь, исполнителя, знак, оплату, админку, а также закрытые
пути (`..`, скрытые файлы) и лимит попыток кода.

Dev-сервер фронтенда (`npm run serve`) по-прежнему работает — без кабинета: там
кнопка «Задание» кладёт задание папкой в `render/jobs/` для ручного рендера.
