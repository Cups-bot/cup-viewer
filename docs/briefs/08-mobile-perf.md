# Этап 08 — Mobile Design Mode, производительность, совместимость

Три части, отдельные сессии: 08a mobile/tablet, 08b загрузка и кэш, 08c адаптивное качество (P1 — только после «ок» человека).
Читать: §45–§52, §42; аудит раздел 1 (хостинг и заголовки).

## 08a — Mobile и tablet Design Mode
1. Нижняя панель `[Стакан] [Дизайн] [Материал] [Ещё]`; «Ещё»: фон, сцена, экспорт, 360, Client View (§45). Model Picker и Export Center — полноэкранные bottom sheets.
2. Tablet §46: landscape — desktop-раскладка, portrait — mobile-контролы с увеличенными sheets. Брейкпоинты — в CSS-переменных, в план.
3. Жесты не конфликтуют со скроллом sheet'ов; цели нажатия ≥ 44×44 px.

## 08b — ленивая загрузка и кэш
1. Стартовая загрузка — только §50: UI, ядро three, выбранная модель, её текстура, студия. Сцены, HDR, экспорт, энкодер — по требованию. Список чанков до/после и вес каждого — в отчёт.
2. Ассеты с fingerprint в имени → `Cache-Control: public, max-age=31536000, immutable`; HTML и ответы `get-snapshot` — `no-store` (§51). Где выставлять — по аудиту раздел 1; если хостинг заголовки не даёт настроить — остановись, 2 варианта.

## 08c — адаптивное качество (P1)
Уровни High/Medium/Low из §48 по характеристикам устройства (`renderer.capabilities`, `UNMASKED_RENDERER_WEBGL`, DPR, deviceMemory при наличии) + понижение на ходу при устойчивом FPS < 30 в течение 3 с. Не меняются: геометрия, цвет, тип материала. `render:check` снимается на High.

## Проверка для всех частей
- dev-оверлей FPS (`?debug=perf`, в прод отключён)
- `docs/qa/compat.md` — таблица по матрице §52: устройство, браузер, FPS в 3D/сцене, найденные проблемы. Реальные устройства проверяет человек; агент готовит таблицу и сценарий прохода на 10 шагов.
