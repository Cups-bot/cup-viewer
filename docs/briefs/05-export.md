# Этап 05 — Export Center

Бюджет размышления: think.
Читать: §20, §21, §29, §50; аудит раздел 8.

## Цель
Одна кнопка «Экспорт» даёт PNG/JPG текущего вида, ZIP из 4 ракурсов и запись 360° из одного окна.

## Требования
1. Модуль экспорта грузится динамическим импортом при первом открытии окна (§50). Видеоэнкодер — только при старте записи.
2. Изображение: PNG | JPG (качество 0,92), размер 1920×1080 | 2048×2048 | текущий вид. Рендер во внеэкранный render target нужного размера; кадр без UI; стакан целиком в кадре при любом соотношении сторон — сохраняй вертикальный FOV, при необходимости отодвигай камеру по текущему направлению.
3. Цвет экспорта = цвет на экране: тот же toneMapping и colorSpace. Проверка: экспорт 1600×1200 из capture-состояния против кадра `render:check` — порог этапа 01.
4. 4 ракурса: пресеты `front, right, back, left` из этапа 03, одна дистанция, фон и свет. ZIP через ту zip-библиотеку, что уже есть (аудит раздел 8). Имена `<modelId>_<materialId>_<view>.png`, без имени исходного файла.
5. 360°: существующая логика записи без изменений, меняется только UI (видео, опционально + кадры).
6. Операция > 1 с — прогресс с реальным числом кадров; кнопки заблокированы; повторный запуск игнорируется. Ошибка — §42 «Ошибка экспорта».
7. Память: render targets и canvas освобождаются после каждого экспорта. Замер: 5 экспортов 2048×2048 подряд — рост памяти GPU/JS-heap в отчёт.
8. Capabilities: в client — только current view, unwrap, 360, preview (§29); проверка через ModeController.

## Не-цели
- прозрачный фон (§20)
- изменение логики 360-записи

## Готово
- [ ] `render:check` зелёный
- [ ] проверка п.3 — числа ΔE в отчёт
- [ ] ZIP 4 ракурсов: 4 файла, одинаковая дистанция (положение кромки по вертикали отличается ≤ 2 px)
- [ ] 5 экспортов подряд без роста памяти > 10 %
