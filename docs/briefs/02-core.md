# Этап 02 — ViewerState, ModeController, каталоги данных

Рефакторинг: видимое поведение и кадры не меняются. Бюджет размышления: think hard.
Читать: §4, §18, §36–§39, §60; аудит разделы 2, 5, 6, 7.

## Цель
Всё состояние Viewer живёт в ViewerState, права режимов задаёт ModeController, а модели, материалы, фоны, сцены и бренды описаны данными в `catalog/`.

## Требования
1. ViewerState — модуль без зависимостей: `get()`, `set(patch)`, `subscribe(keys, fn) → unsubscribe`. Поля §36 плюс `tab: '3d' | 'unwrap' | 'scene'`. Уведомления батчатся в один микротаск — один рендер на пачку изменений.
   Валидация `set`: неизвестный ключ → throw в dev, warn в prod; `modelId` не из каталога → throw; `materialId` несовместим с моделью → `defaultMaterial` модели + warn.
2. DOM перестаёт быть источником истины: все места из аудита раздел 5 переведены на ViewerState.
3. ModeController: `mode ∈ {design, client}` определяется точкой входа, не query-параметром. Таблица capabilities §37 — `Object.freeze`. Каждое действие, меняющее модель, дизайн, материал, публикацию или полный экспорт, проверяет capability; в client — отказ + `console.warn`, state не меняется.
4. Разделение бандлов: две точки входа — design и view (имена и маршруты предложи в плане). Код загрузки, model picker, material picker, публикации импортируется только из design-входа. Движок — общий модуль.
5. Каталоги:
   - `catalog/models.json` — поля §38 + `searchTerms: string[]` (для этапа 03) + `printType` (для §25);
   - `catalog/materials.json` — перенести только существующие материалы, параметры байт-в-байт;
   - `catalog/backgrounds.json` — перенести текущий sweep как есть;
   - `catalog/scenes/<id>/scene.json` + ассеты — перенести существующую сцену по схеме §18;
   - `catalog/brands.json` — formacia, mycups: `logo`, `accent`, `favicon`, `title`. Логотипы дадут отдельно — пока пути к заглушкам, в отчёт.
6. Валидация каталогов при загрузке — своим кодом, сообщение с файлом и полем. Сломанная запись одной модели не роняет весь каталог: запись исключается + error в консоль.
7. Ветвления по конкретным моделям из аудита раздел 6 — перенесены в поля каталога.
8. Unit-тесты на `node --test` (без новых зависимостей): ViewerState (батчинг, валидация, отписка), ModeController (каждая capability в каждом режиме), валидатор каталогов (битая запись, пропущенное поле, неизвестный материал).

## Не-цели
- никаких новых функций и видимых изменений UI
- не добавлять материалы, фоны, сцены (кроме тестовой копии, см. «Готово»)
