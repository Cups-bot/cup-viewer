# CupViewer v2: сайт с фотореал-рендером

Согласовано владельцем · 2026-09-25

Решения владельца от 2026-09-25 отмечены [владелец]. Мои предложения по пунктам,
которые владелец доверил мне, отмечены [предлагаю]. Всё делается локально на
этом компьютере; выгрузка на сервер — отдельный этап по команде владельца.

---

## 1. Что меняется

**Было (cup-viewer, концепция v1.0).** Инструмент типографии: сотрудник из
белого списка собирает вид стакана и отдаёт клиенту ссылку. Аккаунтов, истории
и оплаты нет.

**Будет.** Публичный сайт для всех: 3D-просмотр и превью кадра бесплатно,
фотореалистичный рендер — за токены. 3DCupRender становится движком рендера
сайта, а его отдельной панели не будет: этап 4 ТЗ переходит в сайт.

## 2. Пользователи и роли

[владелец] Сайт для любых пользователей: клиенты, дизайнеры, менеджеры.
Сотрудников с безлимитом нет, администратор нужен.

| роль | что может |
|---|---|
| гость | 3D-просмотр, макет, материалы, превью кадра; ничего не сохраняется |
| пользователь | всё, что гость, плюс рендеры за токены и галерея |
| администратор | пользователи, токены (начислить, вернуть), очередь рендера, платежи |

Сотрудник типографии — обычный пользователь. Нужны ему токены — их начисляет
администратор.

## 3. Что бесплатно и что за токены

| что | цена |
|---|---|
| 3D-просмотр, макет, материалы, кадры из браузера (Export Center) | бесплатно |
| превью кадра: сцена, ракурс, формат, 1–2 стакана, расстановка | бесплатно |
| фотореал, длинная сторона до 1600 px | 1 токен [владелец] |
| фотореал для печати, длинная сторона до 3000 px | 3 токена [владелец: 2–3] |
| убрать водяной знак с бесплатного кадра | 1 купленный токен [владелец, 2026-09-27], без повторного рендера |
| видео-оборот, пакет ракурсов | позже, цена после замеров |

Правила:
- цена видна на кнопке до запуска («Рендер · 1 токен»);
- цену считает сервер по параметрам задания, браузеру не доверяем;
- токены при постановке в очередь резервируются, после кадра списываются, при
  сбое рендера возвращаются сами;
- второй стакан в кадре цену не меняет.

## 4. Бесплатные рендеры и водяной знак

[предлагаю] 3 приветственных токена после подтверждения почты. Действуют 30
дней, чтобы ими пользовались, а не копили.

Кадр, оплаченный приветственным токеном, выдаётся в полном размере с небольшим
полупрозрачным знаком сайта в углу. Чистый кадр хранится; кнопка «Убрать знак»
стоит 1 купленный токен и видеокарту не занимает. Кадры за купленные токены —
без знака. [владелец, 2026-09-27] Приветственными токенами знак не снимается:
иначе из трёх бесплатных выходил чистый кадр, и знак не вёл к покупке.

Почему так: человек видит настоящее качество, а не урезанную картинку; знак
рекламирует сайт, когда кадр пересылают; снятие знака почти ничего нам не стоит,
но мотивирует купить пакет.

## 5. Оплата

[предлагаю] На старте — пакеты токенов, разовая покупка. Подписки нет: для неё
нужны автоплатежи, а пакеты проще и для самозанятого, и для пользователя.
Подписку добавим, если появятся постоянные клиенты, например менеджеры,
которые рендерят каждую неделю.

- Линейка для примера: 10, 30 и 100 токенов, чем больше пакет, тем дешевле
  токен. Цены — после замера себестоимости (§9).
- Купленные токены не сгорают; приветственные — через 30 дней.

[владелец] Юрлица нет, владелец — физлицо. Самый простой законный путь —
самозанятость (налог на профессиональный доход):
- регистрация онлайн в приложении «Мой налог»;
- 4 % с оплат физлиц, 6 % с оплат организаций, лимит 2,4 млн ₽ дохода в год;
- онлайн-касса не нужна: чеки формируются в «Мой налог»;
- платёжные сервисы для самозанятых (например, ЮKassa, Robokassa) умеют
  отправлять чеки сами.

Что проверить к выгрузке, лучше с бухгалтером или юристом: подходит ли продажа
рендеров под самозанятость, условия эквайринга, оферта, политика обработки
персональных данных и согласие на неё, уведомление Роскомнадзора об обработке
персональных данных. Локально всё это не нужно: оплата — тестовая заглушка.

## 6. Вход

[предлагаю]
- **Почта и одноразовый код** (6 цифр) — основной вход, без паролей. Код
  подтверждает почту, после первого входа начисляются приветственные токены.
- **«Войти через Яндекс»** — второй кнопкой: аккаунт у многих есть, и он уже
  подтверждён. Та же почта — тот же аккаунт.
- Позже, если попросят: VK ID, Telegram.

Защита бесплатных токенов:
- одноразовые почтовые домены не принимаются;
- приветственные токены — один раз на почту;
- ограничение числа новых аккаунтов с одного адреса за сутки;
- у бесплатных пользователей в очереди не больше одного задания.

Локально письма не уходят: код печатается в консоль сервера.

## 7. Сценарий пользователя

1. Стакан и макет — как сейчас в cup-viewer.
2. 3D: крутит, смотрит, скачивает кадры из браузера.
3. «Фотореал»: сцена (7 рабочих), ракурс, формат 1:1 / 3:4 / 4:5, второй
   стакан, расстановка мышью. Превью совпадает с будущим кадром.
4. «Рендер · 1 токен». Гостю — вход. Задание уходит в очередь; видно место в
   очереди и ожидаемое время.
5. Готово: уведомление на сайте, кадр в галерее, скачать PNG.
6. Галерея: кадры 30 дней, «повторить с изменениями», удалить.

## 8. Архитектура

```
Браузер: cup-viewer — 3D, превью кадра, кабинет, админка
   │  HTTPS, JSON
API (Python, FastAPI): вход, токены, задания, файлы, админка
   │  база: SQLite локально → PostgreSQL на сервере
   │  файлы: папка локально → S3 на сервере, автоудаление через 30 дней
Очередь заданий (таблица в той же базе)
   │  исполнитель сам приходит за заданием
Рендер-исполнитель: Python + Blender (движок 3DCupRender), возвращает кадр
```

- **Почему Python и FastAPI.** Движок рендера уже на Python: каталог, задания,
  проверки — общий код. FastAPI лёгкий и сам описывает API. Прежнее правило ТЗ
  «ничего через pip» для сайта отменяется: зависимости фиксируются в
  `requirements.txt`, всё в отдельном виртуальном окружении.
- **Почему не Supabase** (был в плане cup-viewer, этап 06). Персональные данные
  пользователей из России по закону о локализации хранятся на серверах в России.
  Своя база на Timeweb это решает. Контракт клиентских ссылок cup-viewer
  (`publish-snapshot`, `get-snapshot`) переносится в наш API как есть.
- **Исполнитель отдельно от сайта.** Он сам забирает задания по HTTPS. Его можно
  запустить на этом ноутбуке, на ПК с видеокартой дома или на арендованном
  GPU-сервере, и сайт при этом не меняется. Исполнителей может быть несколько.
- **Нагрузка локально.** Docker не нужен. Один исполнитель в лёгком режиме:
  приоритет ниже обычного, 4 потока, пауза между заданиями.

## 9. Экономика

- Себестоимость кадра = цена часа видеокарты × время кадра, плюс хранение и
  трафик. Время кадра замерим на сервере-кандидате, от него цена токена — с
  запасом на комиссию эквайринга и налог.
- Одна видеокарта — очередь. Показываем ожидаемое время по истории похожих
  заданий; купленные токены идут в очереди раньше приветственных.

## 10. Хранение и безопасность файлов

- [владелец] Макеты и кадры хранятся 30 дней, потом удаляются сами. В галерее
  видно, сколько осталось. Записи о заданиях и платежах (без файлов) хранятся
  дольше — для учёта.
- Исходный макет уходит только на наш сервер в рендер; другим пользователям —
  никогда (правило cup-viewer сохраняется).
- Принимаем только PDF, PNG, JPG с ограничением размера. Файлы Blender и прочее
  не принимаем: в `.blend` может быть исполняемый код.

## 11. Хостинг (к выгрузке)

[владелец] Timeweb Cloud, там уже лежит Color Palette. Предварительно:
- сервер под сайт и API;
- PostgreSQL;
- S3-хранилище с правилом удаления через 30 дней;
- видеокарта: проверить GPU-серверы Timeweb; если цена не подойдёт — другой
  российский провайдер или свой ПК-исполнитель на старте.

  catalog/   cups.json — единый каталог (общие поля + web + render); models.json собирается из него

- Тяжёлые файлы Blender (сцены 4.blend на 196 МБ, модели, текстуры) — вне git:

  на диске (потом S3). Проверка — `python render/engine/tools/assets.py check`.
- Правила cup-viewer сохраняются для `web/`: `render:check`, один движок и одно
  состояние, стек фронта, «цвет макета важнее эффектности».

## 15. Ответы владельца (2026-09-25)

1. Название — CupViewer. Домена пока нет, работаем локально.
2. Письма «рендер готов» не нужно, хватит уведомления на сайте.

## 16. Решения по этапу Б (владелец, 2026-09-26)

1. Фото-сцена кафе уходит с сайта: её место занимают 7 сцен рендера. Кадр кафе
   в `render:check` заменяется кадром новой сцены (эталон — с «ок» владельца).
2. В режиме «Фотореал» стакан проходит то же цветовое преобразование, что и в
   рендере, — Khronos PBR Neutral, своим шейдером (в three 0.160 его нет).
   Студийный 3D-режим не меняется.
3. Стаканы в сцене **не перемещаются**, только поворачиваются: жестом по кадру
   и ползунком. Места стаканов выбирает раскладка (одиночный — место героя
   сцены, пара — в линию по центру), сайт передаёт их в задание (`pos_mm`), и
   рендер ставит стаканы туда же.
4. Клиент по ссылке видит сцену такой, какой её собрал пользователь (сцена,
   ракурс, формат, стаканы с поворотами), и только смотрит. — Отменено
   2026-09-27, см. §17.

## 17. Решения владельца (2026-09-27, после аудита)

1. **Общий сервис — ссылок клиенту нет.** Клиент сам приходит на сайт. Кнопка
   «Ссылка клиенту» и API ссылок (`snapshot-assets`, `publish-snapshot`,
   `get-snapshot`) убраны; сервер `view.html` не отдаёт. Код страницы клиента
   (`view.html`, Client Mode) пока в репозитории — его удаление отдельным шагом,
   с правкой CLAUDE.md.
2. **Знак снимается только купленными токенами** (§3, §4).
